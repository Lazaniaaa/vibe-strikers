# Dedicated lobby island

The lobby now shows its own compact floating rooftop, with a round pedestal, bench, lamp, two parcels, flower boxes, topiary and two flags. Flag colours come directly from `TEAM_COLORS.ally` / `enemy`. All other island geometry colours use Endesga 32. The PLAY / CHARACTERS / SETTINGS cards and behaviour remain as approved; the Toy Town label is removed.

## Isolation from the game

- `src/maps/lobby.ts` is a separate public entry. The normal `src/maps/index.ts` does not import it.
- `mapIds` still contains exactly the five playable maps. `loadMapData('lobby-island')` throws.
- GameApp, OnlineApp, postfx.ts, the game sky, buildMap, all five game-map JSON files, main.tsx and hud.css are byte-identical to task entry.
- Configuration outside MENU, including LIGHTING, RENDER, TEAM_COLORS and MAP_ID, is byte-identical.
- No package, gameplay, network, server, character or weapon file was edited. No commits.
- `scope-guard.json` records the checked boundary. The timing-only report regenerated by the full map verifier was restored to its exact task-entry version.

## Lighting and shadows

All lobby lighting is in MENU: warm sun intensity 2.5, cool ambient 0.75, hemisphere 0.65, front key 2.6 and rim 1.1. A menu-only screen gradient keeps the blue sky visible with the downward camera; the fog matches its horizon.

Every character mesh casts a shadow and has `receiveShadow=false`. Only the pedestal receives that shadow. Props and clouds neither cast nor receive live shadows; static island boxes use the existing cached vertex-colour baked AO. One 1024 shadow map covers 5 × 5 m around the pedestal, with PCFSoft, bias −0.00008 and normalBias 0.018. Its projection is fixed while the character turns. No blob fallback was needed.

The first visual review caught overlapping pedestal caps. The final mesh has a recessed base cap, a raised inset disc and an uncapped side skin, removing the radial depth-fighting artefact. It remains one merged mesh using the same Lambert material as the boxes.

## Performance

Foreground steady-state menu measurements on this machine, with all 33 portraits ready, pixel ratio 1. These are one-second frame windows, not a cross-device benchmark. Device pixel ratio is capped by MENU (1.25) and RENDER.

| Viewport | FPS | Draw calls including shadow pass | Triangles including shadow pass | Bare-body screen height | Portraits |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1366 × 768 | 60.18 | 19 | 12,762 | 40.5% | 33/33 |
| 1920 × 1080 | 60.16 | 19 | 12,762 | 40.2% | 33/33 |

No page scrolling at either size. Tiny height variation comes from the camera sway. Compared with the previous lobby's 50,978 submitted triangles, the new scene submits about 75% fewer triangles, while adding the live character shadow.

The island contains **93 static boxes and 8 cloud instances**. Full island geometry is **9,160 triangles / 6 meshes**, including the merged pedestal and one InstancedMesh for all clouds. The clouds move as one existing object; no matrices or geometry are rewritten in the frame loop. Initial CPU construction with baked AO measured **176.38 ms** in the independent verifier and **117.10 ms** on the recorded browser re-entry (browser cold/re-entry samples ranged approximately 90–140 ms during review). The normal frame has no geometry/material creation, AO work or allocations of Three.js objects.
